# CatWorld Implement Slice

This is an internal worker skill. Execute it only when
catworld-implement-parent supplies one explicit bounded slice handoff and an
isolated local branch/worktree. A direct user request, GitHub issue reference,
pull request, incomplete handoff or unassigned worktree is a stop; return the
request to the parent rather than inferring scope.

The handoff is the complete implementation contract. Do not fetch or reinterpret
the full parent issue, and do not read the parent's complete spec.md, plan.md or
tasks.md unless the handoff explicitly identifies one bounded excerpt or
reference needed for the assigned work.

## Required handoff

Require all of these fields before editing:

- parent issue number and title;
- slice ID and title;
- objective and required observable or technical behavior;
- relevant approved decisions and feature-wide invariants;
- concrete assigned responsibilities and source surfaces;
- integrated prerequisite behavior already present in starting HEAD;
- explicit exclusions, prohibited paths and prohibited actions;
- permanent-test authorization and exact ceiling;
- required validation commands/evidence and freshness expectation;
- exact starting commit; and
- expected local branch and absolute isolated worktree path.

A correction handoff must also include the original slice handoff, the precise
qualification/global/rebase finding, the current local head and the allowed
correction boundary. Missing context that would require a product,
architecture, authorization, persistence, shared-contract, UX,
correctness-sensitive, operational or scope decision is a blocker, not an
invitation to choose.

For a dependency repair classified as `global correction`, the handoff may also
name an exact parent-authorized mechanical compatibility surface in an already
integrated consumer. Require the handoff to state why the result is uniquely
determined by the corrected producer contract and preserves the consumer's
approved semantics. This is a bounded source-surface exception, not semantic
ownership transfer. The worker must not infer, expand or self-classify it;
ambiguous or behavioral fallout is a blocker.

## Authority and isolation boundaries

Before implementation, read within the assigned worktree:

- AGENTS.md;
- .specify/memory/constitution.md;
- docs/ARCHITECTURE.md;
- this skill; and
- only the current source files and bounded references needed by the handoff.

Treat current source as the implemented starting state. The parent handoff
overrides neither repository governance nor the constitution. If they conflict,
stop and report the exact conflict.

You own only the assigned slice and worktree, plus an exact mechanical consumer
surface when the dependency-repair exception above explicitly authorizes it.
Other workers may be changing other worktrees, so do not revert, overwrite or
infer their work. Adapt only to prerequisite behavior already present in the
supplied starting HEAD.

Do not:

- run any Spec Kit skill or command;
- create, edit, delete, commit or publish files under specs/ or .specify/;
- fetch or reinterpret the complete parent issue;
- expand the handoff, execution map, dependency graph or test policy;
- coordinate, inspect for implementation decisions, or mutate another
  worktree;
- spawn, delegate or hand off any working-tree mutation to another agent;
- switch branches or create, delete, move, add, remove or clean branches or
  worktrees;
- push or otherwise publish the local branch;
- open, update, review or merge a pull request;
- modify GitHub issues, labels, comments, relationships or other remote state;
- amend, squash, force, reset away work, or rewrite published history; or
- perform parent qualification, integration, final validation or delivery.

The only rebase-related exception is a bounded parent-issued correction for a
rebase already positioned in this same worktree. Resolve only the listed
deterministic conflicts and continue/abort only as the parent directs. Do not
initiate an unrelated rebase or merge.

## 1. Verify local state

Before editing:

1. Resolve the current absolute worktree path and branch.
2. Confirm both exactly match the handoff.
3. Confirm HEAD equals the handoff's starting commit for an initial/global
   handoff, or its recorded current head for a follow-up correction.
4. Require git status --porcelain to be empty, except for an explicitly
   described parent-positioned rebase conflict in a correction handoff.
5. Confirm the branch is local and the handoff contains no delivery authority.

Stop on any mismatch. Do not repair an unexpected branch/worktree state by
switching, resetting, cleaning or guessing.

## 2. Apply the supplied permanent-test policy

The parent has already decided authorization from the issue, constitution and
canonical plan. Treat the supplied authorization as a ceiling, not a target.

- When permanent coverage is prohibited, create or broaden no maintained test,
  fixture, helper, scenario, assertion or parameterized case.
- When specific coverage is authorized, add no more than the named responsible
  behavior/files/scenarios and only when it protects a realistic regression
  not adequately covered by existing validation.
- Minimal non-broadening maintenance to an existing test is allowed only when
  the handoff permits it and the approved implementation directly requires it.
- Generated or discovered implementation complexity cannot independently
  broaden authorization.

If the assigned behavior cannot be implemented safely within the test ceiling,
stop and request a parent decision. Still run every supplied existing-suite,
build, inspection or temporary/manual validation command.

## 3. Implement only the slice

1. Inspect the smallest current-source surface needed to reconstruct the
   assigned behavior.
2. Compare the handoff with current prerequisite behavior before changing a
   file. Report a blocker when the starting code lacks a promised prerequisite
   or contains an incompatible approved contract.
3. Implement every assigned responsibility and nothing outside it. Follow the
   existing architecture and project patterns unless the handoff contains an
   approved replacement.
4. Update a source-of-truth document only when it is explicitly assigned or the
   bounded implementation would otherwise make that approved source stale.
   Stop if such an update falls outside the permitted paths.
5. Do not perform unrelated cleanup, opportunistic refactors, speculative
   abstractions or sibling fixes.

For a pre-integration correction, address only the parent's exact finding and
revalidate the complete slice. For a global correction, implement only the
listed gap attributed to this existing slice. Normal follow-up commits are
allowed; never amend earlier commits merely to produce one commit per slice.
For a dependency repair, change an already integrated consumer only within the
exact parent-authorized mechanical compatibility surface; stop if the result
would select or change consumer semantics.

## 4. Validate fresh behavior

Run every command/check required by the handoff and every directly affected
validation needed to keep that evidence meaningful. When native MySQL evidence
is explicitly required, follow the isolated temporary procedure supplied by
the parent and never touch the normal CatWorld development stack or data.

If a relevant change occurs after evidence was collected, rerun it. Record each
result as one of:

- passed;
- failed;
- skipped;
- timed out;
- interrupted;
- partial;
- stale; or
- not revalidated.

Only fresh passed evidence satisfies the handoff. Do not hide failure with a
summary and do not substitute an unrequested new permanent test for unavailable
required evidence.

## 5. Review the complete slice diff

Before committing, inspect the complete handoff-start-to-working-tree diff and
changed-file list.

Confirm:

- every assigned responsibility is present;
- every changed line/file is necessary for this slice;
- prohibited and parent-owned surfaces are untouched;
- specs/, .specify/, unauthorized sibling-slice surfaces and orchestration state
  are absent; any consumer-slice change is exactly the parent-authorized
  mechanical compatibility surface;
- no unauthorized permanent coverage was added or broadened;
- validation is fresh after the latest relevant change; and
- no material decision or blocker remains.

Remove only this worker's own uncommitted out-of-scope change when safe. Never
discard pre-existing or another worker's changes. Stop and report when clean
remediation is not certain.

## 6. Commit locally and finish clean

Create one or more normal commits on the assigned local branch using concise
English conventional titles. One commit is desirable when natural, but commit
count is not an invariant.

Do not amend, squash, merge, push or rewrite history. A correction adds a normal
follow-up commit. After committing:

- confirm every reported commit exists;
- confirm the branch contains the complete slice from the recorded starting
  commit; and
- require git status --short to be empty.

If the branch cannot finish clean, stop and report every dirty path. Do not
clean or reset it.

## 7. Return the delivery report

Return to the parent:

- parent issue and slice ID/title;
- delivery kind: initial, pre-integration correction, rebase correction or
  global correction;
- absolute worktree path and local branch;
- starting commit, final local HEAD and every new commit SHA in order;
- changed files and concise behavior summary;
- validation commands with explicit statuses and freshness;
- permanent-test authorization/ceiling and final test-diff result;
- prohibited-surface and scope-drift review result;
- remaining risks or limitations;
- blocker, or explicit “none”;
- exact git status --short output; and
- confirmation that nothing was pushed, no GitHub state changed and no other
  worktree was mutated.

Do not claim qualification or integration; those are parent decisions.

## Stop conditions

Stop without delivery commits that misrepresent completion when:

- the handoff is missing, incomplete, contradictory or not for this worktree;
- local branch, path, starting head or cleanliness is unreliable;
- repository governance conflicts with the handoff;
- required prerequisite behavior is absent;
- implementation needs work outside assigned/prohibited scope;
- a missing material decision must be made;
- required permanent coverage would exceed the supplied ceiling;
- required validation fails or cannot become fresh within scope;
- a rebase conflict is nondeterministic or outside the bounded correction;
- the final diff contains unexplained or unauthorized changes; or
- the branch cannot finish clean.

Preserve the worktree and useful local commits. Do not switch, clean, delete,
push or attempt automatic recovery.

## Done when

- The complete bounded slice and only that slice is implemented.
- Supplied test authorization and validation requirements are satisfied with
  fresh evidence.
- The full diff contains no prohibited or unrelated surface.
- One or more normal local commits contain the delivery and the branch is
  clean.
- The parent receives the exact commits, paths, evidence, risks and blocker
  state needed for independent qualification.
- No Spec Kit artifact, remote state, other worktree or delivery operation was
  touched.
